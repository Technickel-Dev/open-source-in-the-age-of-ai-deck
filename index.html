The basics

What is Open Source?

Software whose source code is public, shared under a license that lets anyone use it.

Read it

The code is public

Anyone can see how it works, learn from it and check what it does.

Change it

Anyone can improve it

Fix a bug, add a feature or improve the docs, then send it back to the project.

Share it

The license says you can

Use it, fork it and build on it, within the terms of its license.

Open Source in the age of AI · Technickel
Keep this short. Open Source means the source code is available under a license that allows use, study, modification and sharing. Examples people know: Linux, Python, React, VS Code. The license matters, so check it before reusing anything.

Contributing in the age of AI

Don't be the reason PRs stopped counting

  1. 01

    Read the rules

    CONTRIBUTING.md, and the project's AI policy if it has one.

  2. 02

    Talk first

    Comment on the issue before you open a PR.

  3. 03

    Own every line

    If AI wrote it, you reviewed it, tested it and can explain it.

  4. 04

    Quality over quantity

    One thoughtful PR beats ten drive-bys. Disclose AI help when asked.

Open Source in the age of AI · Technickel
Etiquette for contributing with AI. This ties back to why PRs stopped counting: low-effort AI PRs burned maintainers out. Follow the project's rules, talk before you code, and stand behind every line you send.

Contributing in the age of AI

It looks bad on you

A PR you can't explain costs you trust.

It makes the maintainer's life harder

They review, debug and fix what you couldn't.

Prove it works · and let AI automate the proof

  • ✓Tests
  • ✓Screenshots
  • ✓Short recordings
  • ✓Before / after

Proof helps the review. It never replaces understanding the change.

Open Source in the age of AI · Technickel
If you can't explain what the AI wrote, don't send it. It looks bad on you and it makes the maintainer's life harder. Tests, screenshots and short recordings that prove the change works are supplemental and really help reviewers, and AI can generate and automate a lot of that proof. But they never replace understanding the change.

The Open Source Gazette

Bulletin

PHP Cracked Open! AI-Found Flaws Hit Millions of Sites

"PHP2Shell" · CVE-2026-109618 and CVE-2026-109619 · severity 9.2

Two critical remote-code-execution bugs in PHP core, found by Wiz Research with help from frontier AI models, reach nearly every PHP version back to 5.4, the language Wiz says powers 70% of websites. Reported in August and patched on October 21 (8.5.12, 8.4.27, 8.3.36, 8.2.35), they are already being used against exposed PAN-OS management interfaces. Palo Alto counts over 22 million potentially vulnerable instances.

Extra! Extra!

AI Gateway Seized by Attackers!

LiteLLM · CVE-2026-42271 · on CISA's exploited list

A command-injection hole in a popular open source AI gateway let anyone with an API key run commands on the host. Chained with a Host-header bug, no key was needed. CISA listed it on June 8, five weeks after the fix. Attackers planted web shells and lifted credentials.

Agents Outwitted

Coding Agents Tricked by a Git Config

"GitSpawn" · eight flaws in seven tools

Manifold Security found a repo's own git settings can name a command that AI coding agents run outside their sandbox, without asking. Fixed in Claude Code, Cursor and goose; others still ran it on retest. No exploitation reported.

The moral: AI now finds bugs faster than ever, and so do attackers. Patch fast, sandbox what you run, and read the advisories.

Sources: Wiz Research and Palo Alto Unit 42 (PHP2Shell) · Cloud Security Alliance and CISA KEV (LiteLLM) · Manifold Security via The Hacker News (GitSpawn)

The point: it is ordinary software with ordinary bugs, but AI is speeding up both finding and exploiting them. Verify details against the primary advisories before quoting.
