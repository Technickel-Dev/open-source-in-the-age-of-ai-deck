> What is Open Source?

Start with the basics

The basics

What is Open Source?

Software whose source code is public, shared under a license that lets anyone use it.

Read it

The code is public

Anyone can see how it works, learn from it and check what it does.

Change it

Anyone can improve it

Fix a bug, add a feature or improve the docs, then send it back to the project.

Share it

The license says you can

Use it, fork it and build on it, within the terms of its license.

Open Source in the age of AI · Technickel
Keep this short. Open Source means the source code is available under a license that allows use, study, modification and sharing. Examples people know: Linux, Python, React, VS Code. The license matters, so check it before reusing anything.

Open Source in the age of AI · Technickel
Quick tour, not legal advice. The bar runs from permissive licenses (MIT, BSD, Apache 2.0), which let you do almost anything with a notice, to copyleft licenses (LGPL, GPL, AGPL), which require derived work you distribute to stay open under the same terms. The grid shows what each lets you do: all four allow commercial use and changes; MIT and Apache let you ship changes closed; GPL and AGPL do not; only the AGPL also counts offering it as a network service as distribution. Apache 2.0 also grants patent rights. The red end of the bar is the copyleft licenses; past it, the dark end holds source-available licenses (BSL, SSPL, Elastic), where you can read the code but the license restricts what you do with it, so they are not open source by the usual definition. Code with no license is not open source either: the author keeps all rights. For anything at work, check with Legal.

> The AI

Walls go up, doors open

Contributing in the age of AI

Own your AI output

If you don't know what it's doing, don't contribute it. Don't be a MEAT proxy.

It looks bad on you

A PR you can't explain costs you trust.

It makes the maintainer's life harder

They review, debug and fix what you couldn't.

Prompts that help you understand

  • >"Walk me through this diff line by line, like I'm new to this codebase."
  • >"What could this change break? List the edge cases and risks."
  • >"What would a maintainer push back on, given CONTRIBUTING.md and the code style?"
  • >"Explain how X works and why you did it that way instead of the alternatives."

Prove it works · and let AI automate the proof

  • ✓Tests
  • ✓Screenshots
  • ✓Short recordings
  • ✓Before / after

Proof helps the review. It never replaces understanding the change.

Open Source in the age of AI · Technickel
If you can't explain what the AI wrote, don't send it, and don't be a meat proxy: a human who just passes the AI's output along without understanding it. It looks bad on you and it makes the maintainer's life harder. Use AI to interrogate its own output: ask it to explain the diff, list what could break, predict maintainer pushback and explain the parts you'd have to defend. Tests, screenshots and short recordings that prove the change works are supplemental and really help reviewers, and AI can generate and automate a lot of that proof. But they never replace understanding the change.

AI Gateway Seized by Attackers!

LiteLLM · CVE-2026-42271 · on CISA's exploited list

A command-injection hole in a popular open source AI gateway let anyone with an API key run commands on the host. Chained with a Host-header bug, no key was needed. CISA listed it on June 8, five weeks after the fix. Attackers planted web shells and lifted credentials.

Brotli2Shell: Unzipping Data Can Hand Over the Server

CVE-2026-111497 · also "HTTP2Shell" · severity 9.2

A memory-writing bug in Google's Brotli decoder lets crafted compressed data take over any program that unpacks it, and Node.js, Python packages, .NET, Bun and Envoy all bundle it. Patches shipped October 21, and CISA put it on its exploited list on October 27.

Source: BleepingComputer and Cynet

Prompts to learn why it's this way

  • >"Run git blame on this function and summarise why each part changed."

Door three: code looks strange until you know the story. git blame shows who changed a line and when; the commit message links to the PR and issue with the reasoning.
